# 大阪觀光業者每日決策平台 — 商業需求文檔（BRD）

## 1. 商業背景

| 項 | 內容 |
|---|---|
| **業務領域** | 観光 DX + オープンデータ + 地域事業者支援 |
| **產品形態** | **ToB SaaS + B2G 委託混合**（AI chatbot 為核心）|
| **AI 能力** | 大模型應用（RAG-based 自然語言 + 數據維度精準回答）|

**背景描述**：
大阪觀光局已有 DMP（DataVehicle/Vpon 建置）但**數據分發停在戰略部門**，地域業者拿不到能執行的行動建議；観光庁 2025-2030 政策強推「地域事業者活用」+「オープンデータ」，補助金 76 案件採択可申請；CTC/MATCHA 等競品集中在「遊客向 chatbot」，「**業者向 chatbot**」是公認空白。本案以委外/第三方提案身分切入。

---

## 2. 商業目標

| 維度 | Year 1 | Year 2-3 |
|---|---|---|
| **B2G 客戶** | 1 個（大阪觀光局或大阪府 POC 案）+ 3-5 商圈協會 + 3 市町村 | 大阪府 41 市町村覆蓋 50% |
| **業者數** | 200-300 家試用、付費轉化 30-50% | 1,000-3,000 家付費 |
| **對話量** | 月 1-3 萬次 | 月 10-30 萬次 |
| **收入** | **¥22-40M**（PDF 匯出 P1 後加，故較原估略降）| ARR ¥150-300M |
| **核心矛盾解決度** | 業者使用 NPS ≥ 25、回答正確率 ≥ 80% | NPS ≥ 50、正確率 ≥ 95% |

---

## 3. 核心價值主張

**一句話**：為大阪地域業者提供「**用自然語言問、用業者語言答**」的 AI 觀光數據助理，把專業數據翻譯成可下手的行動建議，補完「**數據活用的最後一哩路**」。

| 對象 | 用戶價值 |
|---|---|
| 餐飲/民宿/小型業者 | 自然語言問選址、客群、業種策略；P1 後可購買單次報告取代委託顧問 ¥30 萬+ |
| 商圈協會 | 招商引介白皮書、會員業者集中支援、對市町村申報有量化依據 |
| 市町村觀光課 | 對外招商展示、議會說明、補助金市場依據（**取代シンクタンク ¥500 萬+ 委託**）|

| 對象 | 商業價值 |
|---|---|
| 大阪觀光局 | 既有 DMP 投資的 ROI 擴大、補完最後一哩路、可申請觀光庁補助金分擔成本 |
| 大阪府 | 提升地域業者整體競爭力、推動 EBPM、城市品牌效益 |

## 4. 盈利模式（雙層結構）

### 戰略層（高客單、低頻、撐 ARPU）

| 模式 | 單價 | Y1 件數 | Y1 收入 |
|---|---|---|---|
| **B2G 觀光局/府 委託案**（一次性建置）| ¥15-25M | 1 件 | **¥18M** |
| 招商引介白皮書（商圈/市町村，**P1 後加**）| ¥100-1,000k | 5 件 | ¥1.5M（從 M9 開始算）|
| 業者選址/市場進入報告 PDF（**P1 後加**）| ¥30-100k | 30 件（半年）| ¥1.5M |

### 日常層（低客單、高頻、撐留存）

| 模式 | 單價 | Y1 數 | Y1 收入 |
|---|---|---|---|
| 商圈協會年費 | ¥200-500k/年 | 5 個 | ¥1.75M |
| 市町村年費 | ¥200-500k/年 | 3 個 | ¥0.9M |
| 業者 SaaS 月費 | ¥3-10k/月 | 200 ✕ ¥6k ✕ 6 月均 | ¥7.2M |

**Year 1 合計**：保守 **¥22M** / 中位 **¥30M** / 樂觀 **¥40M**

> 💡 **觀光庁補助金（補助率 1/2、上限 ¥15M）** 可申請，等於觀光局採購時實際自付一半，大幅降低 B2G 簽約門檻。

## 5. 階段拆分（demo + POC 優先）

```
┌──── Phase 0：提案 demo（M1-M2）───────────┐
│  • 純展示用 demo（部分 mock + 部分真實 AI 對話）│

│  • 投入：1-2 FTE、¥3-5.5M                  │
│  • 目標：觀光局/府 提案會議 → 拿到 POC 委託 │
└────────────────────────────────────────────┘
                    ↓
┌──── Phase 1：POC 委託案（M3-M5）─────────┐
│  • 由觀光局/府 預算支付 ¥3-8M             │
│  • 接入示範商圈（黑門市場）               │
│  • 完整 chatbot 跑通 + 50-100 家業者試用  │
│  • 投入：2-3 FTE + 部分外包               │

│  • 全建置 ¥15-25M 或續約 + 業者 SaaS 擴張 │
└────────────────────────────────────────────┘
```

## 6. 投入評估

| 資源 | 預估投入 | 說明 |
|---|---|---|
| **人力** | Phase 0：1-2 FTE / Phase 1：2-3 FTE | PM 1、AI 工程師 1、全端 0.5-1、設計 0.5、業務兼任 0.5 |

> 💡 修正版 BRD 比原 PRD v1（¥61M 投入）大幅瘦身，因為模型降為 Gemini stack（成本 ÷10）+ 階段化策略（POC 預算 cover 一部分）

## 7. 干系人利益分析 ⭐

| 干系人 | 核心利益 | 關係 | 潛在衝突 | 應對策略 |
|---|---|---|---|---|
| **大阪觀光局**（採購方）| 既有 DMP ROI 擴大、業者賦能、補助金獲取 | **主要客戶** | 與既有廠商踩界 | **明確「下游翻譯層」定位**；提案主動引用 DataVehicle 案例為「上游基礎」|
| **DataVehicle + Vpon**（既有 DMP 廠商）| 維持 DMP 合約、防 scope 被搶 | 潛在合作 / 對手 | 視我們為威脅 | **主動接洽**：成為其「對下游配信層」合作夥伴或 OEM；最壞情況走獨立但保持互補論述 |
| **観光庁**（補助金審查方）| 政策推進、補助金效益、業者賦能 | 補助金來源 | 審查嚴格 | 提案符合「観光DX推進事業」要求：オープンデータ + 地域事業者効果指標清晰 |
| **商圈協會**（鈴木們）| 招商、會員服務、活性化 | 中介 + 客戶 | 既有顧問抗拒 | 提供「協會專屬版」、保留策劃職員角色而非取代；招商白皮書為協會帶來收入 |
| **市町村觀光課**（中川們）| 招商、議會說明、補助申請 | 客戶 | 採購法 / 跨單位 | 走公募プロポーザル合規路徑；提供「市町村專屬模板」+ 補助金申請輔助 |
| **餐飲/民宿/小型業者**（田中/山田們）| 決策有依據、不踩雷 | 終端使用者 + 部分付費 | 不會主動用 chatbot | 商圈協會集中導入 + 培訓；自然語言介面強化易用性；P1 後 PDF 報告降低決策門檻 |
| **大阪府民/媒體**（PR 受益方）| 城市品牌、媒體故事 | 間接受益 | 無 | 一年 1-2 次「大阪觀光業者趨勢報告」PR 發布 |
| **我方團隊**（提案方）| 產品成功、可擴張 | 提案方 | 早期現金流壓力 | Year 1 以 B2G 委託撐現金流 → Year 2 展開 SaaS 規模化 |

## 8. 風險與依賴

| 風險項 | 等級 | 應對策略 |
|---|---|---|
| 大阪觀光局個票數據授權拒絕 | **高** | MVP 用 100% 公開資料 + 旅ナカ報告 PDF；個票視為「升級」非前提；可回答 70-80% 維度 |
| AI 回答品質失準（幻覺）導致信任崩盤 | **高** | RAG + Human-in-loop + 多模型交叉驗證 + **Source citation 強制** + 找不到答案誠實說明 |
| DataVehicle/Vpon 擴大 scope | **高** | 「對下游」獨立採購預算定位 + 提案時主動互補論述 + 商圈協會關係護城河 |
| 業者付費意願不及預期 | **高** | MVP 期 50 家試用 + NPS 監測；報告匯出（P1 後）降低決策門檻；不依賴月費 |
| 観光庁補助金政策變動 | 中 | 不單押 B2G、同步 B2B SaaS 自付費路徑 |
| 政府採購法 / 個資合規 | 中 | 行政書士事前審查 + 個人情報保護 SOP + ISMS 認證準備 |
| LLM API 成本暴漲 | 低 | Gemini stack 已比 Sonnet 便宜 10x；備援 GPT-4o-mini |
| 早期現金流斷裂 | **中**（修正後）| 觀光局 POC 委託 ¥3-5M 為 Q2 必達目標；補助金提前 ¥3-7M 入金 |
