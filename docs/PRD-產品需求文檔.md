# 大阪觀光業者每日決策平台 — 產品需求文檔（PRD）

> **反哺確認**：本 PRD 已回讀 Step 3 競品分析（DataVehicle/CTC/MATCHA + Nightmare Scenario）和 MRD 結論。下方 5 個強反哺錨點均融入：核心矛盾、P0 功能、AI 能力 + 人機邊界、兜底策略、核心用戶流程。

---

## 1. 產品概述

| 項 | 內容 |
|---|---|
| **產品名稱** | 大阪觀光業者每日決策平台（工作名）/ 對外：**OSAKA Tourism Action Hub** |
| **產品定位** | 大阪觀光開放數據的「**最後一哩路**」——自然語言問、業者語言答的 AI Chatbot |
| **目標用戶** | P0 餐飲店主、民宿業主、商圈協會策劃職員；P1 市町村觀光課承辦 |
| **核心場景** | 業者用自然語言問選址/客群/業種策略，AI 從大阪觀光資料庫精準提取多維度結果並標示來源 |
| **核心矛盾** | 業者**有真實決策需求**（選址、客群、策略）←→ 大阪 DMP 數據**只能被戰略部門消化**，業者拿不到能下手的回答 |

**產品 scope（Phase 0 + Phase 1）**：
- **Phase 0**（M1-M2）：提案 Demo（6 個典型對話跑通 + Mock UI + 簡報）
- **Phase 1**（M3-M5）：POC（黑門市場示範 + 50-100 業者試用 + 15 題能力清單）
- Phase 2 後續另寫

## 2. 功能需求

### P0 — 必須有（兵力集中 2 個）

| 功能 | 描述 | AI 能力依賴 | 驗收標準 | 對應矛盾 |
|---|---|---|---|---|
| **P0-1 AI 對話引擎**（核心）| 自然語言輸入 → 意圖解析 → RAG 檢索 → 多維度回答 + Source citation + Follow-up 建議 | NLU + RAG + LLM | 15 題能力清單 ≥ 12 題答得出（正確率 ≥ 80%）| 直接解決主要矛盾 |
| **P0-2 業種別畫面/情境**| 業者進站即選業種、UI 自動切換到該業種專屬版（顯示業種專屬 quick-question chips + 上下文自動帶入）；無需註冊；client-side localStorage 記住業種選擇 | 輕量、無 AI | 業種選擇流程 ≤ 30 秒；切換流暢；上下文準確帶入後續對話 | 降低 AI 對話冷啟動門檻 |

#### P0-2「業種別畫面」細節

- 進站首頁：6 個業種大圖示（**餐飲 / 住宿 / 零售・伴手禮 / 旅行社・導覽 / 商圈協會 / 市町村**）
- 點選後：切換到該業種專屬對話介面
  - 顯示 5-8 個業種專屬 quick-question chips（如餐飲業者看「我該主推哪國客」「該做什麼語言菜單」「淡季怎麼定價」）
  - 業種上下文自動帶入後續對話（不用業者每次重提）
- 業種選擇用 client-side localStorage 記住、無需後端儲存
- 業者可隨時切換業種

### P1 — 應該有（V1.0、POC 後展開）

| 功能 | 描述 | AI 能力 | 驗收標準 |
|---|---|---|---|
| **PDF 報告匯出**（變現點）| 對話 thread 一鍵匯出為可帶走的調查報告（含圖表 + 來源說明）；付費升級 ¥30k-100k | PDF 生成（React-PDF / Playwright PDF）| 排版完整、來源清晰、3 秒生成 |
| 多語文案生成器 | 對話結果延伸：一鍵生成繁中/英/韓/簡中 SNS/菜單/Google Maps 文案 | LLM 多語生成 | 4 語版本品質 native review ≥ 80 分 |
| LINE / Email 週度推送 | 主動推送業者所屬業種+地區的本週重點 | LLM 摘要 | 開啟率 ≥ 30% |
| 招商引介白皮書生成（B2G）| 商圈/市町村專屬：自動生成「○○ 進駐商機白皮書」| LLM 長文生成 + 圖表 | 鈴木/中川人工複核通過 |

### P2 — 可以有

| 功能 | 優先級理由 |
|---|---|
| 商圈/市町村「對上申報包」匯出 | 鈴木/中川專屬，POC 後依需求加 |

| 跨市町村比較 | 中川專屬，覆蓋擴張到府全域後再做 |
| 業者用 SNS 自動發布 | 與多語文案生成器整合 |

## 3. AI 能力需求

### 3.1 模型需求（Gemini stack ⭐ 便宜 + 效果 + 日語強）

| 能力 | 模型方向 | 效果指標 | 備選方案 |
|---|---|---|---|
| **意圖分類**（戰略題 vs 資料題） | **Gemini Flash 2.5**（極便宜，<¥0.2/對話）| 正確率 ≥ 95% | GPT-4o-mini、規則匹配兜底 |
| **變數抽取**（slot filling）| **Gemini Flash 2.5**（function calling）| 正確率 ≥ 90% | 預設 dropdown 補抽取失敗 |
| **RAG 檢索** | 向量檢索（Pinecone / Weaviate）+ keyword hybrid | Top-5 召回率 ≥ 85% | BM25 純關鍵字檢索兜底 |
| **答案組裝**（核心）| **Gemini Pro 2.5**（¥2-3/對話）| 業者語言、含 source、正確率 ≥ 80% | GPT-4o-mini 降級、GPT-4o 升級 |
| **Follow-up 建議**| Gemini Pro 2.5 順手做 | 點擊率 ≥ 40% | 預設模板兜底 |

**單次對話總成本**：**¥2-4**

**模型升級路徑**：POC 期 Gemini Pro 2.5 為主；若 Lv.3 改寫題（E1/F1）答得不夠深 → 升 GPT-4o（成本翻 5 倍但仍可控）。

### 3.2 數據需求

| 資料類型 | 用途 | 規模 | 來源 | 合規 |
|---|---|---|---|---|
| 大阪觀光局公開圖表 + 數據集 | RAG 知識庫 | 100-300 份 | datahub.osaka-info.jp | 公開 |
| 旅ナカ調查報告 PDF/PPT | RAG 知識庫核心 | 30-50 份 | 大阪觀光局公開 | 公開、需 ingestion |
| 観光庁訪日統計 | 補充宏觀數據 | 年/季/月度 | 観光庁公開 | 公開 |
| RESAS 地域經濟分析 | 商圈/市町村層級 | 全國 | 內閣府/經產省 | 公開 |
| **個票數據**（P1 升級） | 高粒度回答（區/丁目）| 旅ナカ原始 | **需向大阪觀光局申請授權** | 匿名化 + 用途限定 |
| 評測數據集 | AI 回答正確率評估 | 15 題 ✕ 20 變體 = 300 對話 | 自建（POC 期商圈協會協作）| - |

### 3.3 Prompt / Agent 設計方向

- **Agent 架構**：簡單 ReAct（Intent classify → Retrieve → Compose → Cite）
- **Prompt 策略**：CoT（Chain of Thought）+ Few-shot examples（15 題作為 few-shot 範本）
- **工具調用**：
  - `retrieve_data(query, dimensions[])`：RAG 檢索
  - `cite_source(doc_id, page, q_number, sample_n)`：來源標示
  - `suggest_followup(context)`：產生 3-5 個延伸問題

### 3.4 人機協作邊界

| 環節 | AI 做 | 人 做 | 交接方式 |
|---|---|---|---|
| 意圖解析 | 拆解問題、抽取變數 | — | confidence < 80% 反問澄清 |
| 資料檢索 | RAG retrieval、整理多維結果 | — | 找不到資料明說「不在範圍」 |
| 答案組裝 | 多維度回答 + Source citation | — | — |
| **商業決策** | 提供分析 + 行動建議 | **業者拍板** | 答案結尾標 disclaimer |
| 複雜情境審核 | 自動標註信心度 | **商圈協會職員可幫業者複核** | confidence < 70% 建議「向協會諮詢」 |
| 重大策略決策 | 提供報告匯出（P1 後）| 業者諮詢專業顧問 | PDF 含 disclaimer |

### 3.5 兜底策略 ⭐（反哺競品 Nightmare Scenario：翻譯品質失準導致信任崩盤）

| 失敗場景 | 觸發條件 | 兜底方案 |
|---|---|---|
| **找不到資料（避免幻覺）** | RAG retrieval Top-5 相似度 < 閾值 | **誠實說明**：「此問題涉及 ○○ 資料，目前不在本平台範圍。可參考 [原始資料連結] 或諮詢協會職員」|
| **AI 信心度低** | 答案 confidence < 70% | 給上限/下限區間 + 標「**僅供參考、建議深入諮詢**」|
| 跨資料源衝突 | 兩份資料給出矛盾結論 | 同時呈現兩個結論 + 來源，請業者判斷 |
| 數據過時 | 來源資料 > 18 個月 | 標「**此為 2023 年數據，最新趨勢可能變化**」|
| **超出業者向範圍** | 意圖分類為「政府/決策層」題（如 IR 政策模擬） | 拒答 + 引導：「**本平台聚焦業者經營決策，此問題建議洽詢大阪觀光局戰略部門**」|
| AI API 故障 | 超時或錯誤 | 自動切換 Gemini → GPT-4o-mini；失敗 3 次後人工 LINE 通知 |
| 內容安全 | 出現商業惡意比較（「A 店比 B 店好」）| 拒答 + 引導正面論述 |

## 4. 核心用戶流程

```
業者首次進入：
  網站首頁 → 業種選擇（6 個大圖示）→ 點「餐飲」
   ↓
進入業種專屬畫面：
  • 顯示業種典型問題 chips
  • 對話框可自由輸入
  • localStorage 記住業種選擇（下次直接進對話畫面）
   ↓
業者輸入問題：「我在心齋橋開甜點店，想吸引外國旅客可以怎麼做？」
   ↓
AI 處理（黑盒）：
  ├─ 意圖分類（Gemini Flash 2.5，¥0.2）
  ├─ 變數抽取（Gemini Flash 2.5）
  ├─ 維度推導 + RAG（Gemini Pro 2.5）
  └─ 答案組裝 + Source citation + Follow-up（Gemini Pro 2.5）
   ↓
業者收到回答：
  • 多維度分析（4 區塊：客群/產品/管道/價位）
  • 每點附 📊 資料來源（旅ナカ Q12, n=850, 2023Q3-Q4）
  • 5 個延伸問題建議
   ↓
業者可：
  ├─ 點 follow-up 深挖（→ 回到對話迴圈）
  ├─ 截圖 / 複製內容
  └─ 切換業種（右上角切換鍵）

異常處理：
  資料不足 → 誠實說明「此資料不在平台範圍」
  信心度低 → 給區間 + 建議向協會諮詢
  API 故障 → 自動切換備援模型 + 用戶看到重試提示
```

## 5. 非功能需求

| 維度 | 要求 |
|---|---|
| **性能** | 對話響應 P95 < 8 秒（含 RAG + LLM）/ P99 < 15 秒 |
| **可用性** | SLA 99.5%（Phase 0/1 階段；POC 後正式版升 99.9%）|
| **安全** | 業者帳號加密、對話紀錄不外洩、API key 不寫 client side |
| **個資合規** | 業者輸入若含個資（顧客姓名、電話）自動脫敏；個人情報保護法 SOP |
| **成本** | 單次對話 LLM 成本 ¥2-4（Gemini stack）|
| **可擴展** | 支援模型熱切換（Gemini Pro / Flash、GPT-4o-mini、GPT-4o 任一可主可備）|
| **多語** | 業者介面日語（Phase 0/1 僅日語）；對話輸入支援日/英/繁中 |
| **行動裝置優先** | 手機優先設計（業者常在店裡用手機）|
